# 네이버 블로그 초안 공장 — 마스터 지침

이 폴더는 **초안 공장**이지 **무인 발행기가 아니다.**
사용자가 사진 + 소재 정보 + 한 줄 메모를 주면 → 사진을 직접 보고 글을 쓰고 → 승인 후 네이버 **임시저장**까지 한다. 발행은 언제나 사람이 한다.

작업 시작 전 항상 `data/` 아래 파일을 읽는다. 대화는 세션이 끝나면 사라지지만 파일은 남는다.
**기억할 가치가 있는 건 전부 파일로 기록한다.**

| 항목 | 값 |

## 1. 절대 규칙

1. **API 키 사용 금지.** 모든 AI 작업은 Claude Code 세션 안에서 한다 (구독 토큰만 소모). 외부 LLM API 호출 코드를 만들지 않는다.
2. **발행 금지 — 임시저장까지만.** 태그 입력을 위해 발행 패널을 열어야 하므로, 스크립트는 에디터 로드 직후 **캡처 단계 클릭 리스너**로 진짜 발행 버튼(`button[data-testid="seOnePublishBtn"]`) 클릭을 원천 차단하는 가드(`installPublishGuard`)를 반드시 건다. **어떤 경우에도 이 가드를 제거하지 않는다.** 실패 디버깅 중에도 마찬가지다.
3. **사실 지어내기 금지.** `data/profile.md`와 사진, 그리고 사용자가 준 자료에서 확인된 것만 쓴다. 확인 안 된 정보는 사용자에게 묻는다.
   - **3-1. 협찬 처리(공정위 표시광고법 — 생략 불가).** `/write`마다 협찬·체험단 여부를 반드시 확인한다(메모에 없으면 질문). 협찬이면 `data/sponsored-disclosure.md`의 대가 유형별 문구를 **글 상단 첫 블록**에 일반 `text` 블록으로 넣는다(업체 지정 문구가 있으면 그것이 우선). 협찬 글에 "내돈내산"·"광고 아님" 같은 거짓 부인 표현은 **위법**이므로 쓰지 않는다.
   - **3-2. 스포츠/연예 주제 전용 (이 블로그의 최대 리스크).** 아래 「5. 업종별 필수 정보 체크리스트」의 출처 규칙을 반드시 통과시킨다.
4. **소재는 고객 사례가 아니어도 된다.** 자사 장비·일상 소재도 된다. 단 **서사를 지어내지 말고** 자기 사례임을 정직하게 밝히고 쓴다.
5. **학습 데이터 자동 수집 금지.** `data/trends.md`와 `data/style-profile.md`는 **사용자가 직접 제공한 글**로만 갱신한다. 웹을 긁어 자동 수집하지 않는다.
6. **초안은 사용자 승인 후에만 임시저장.** 승인 없이 `naver_draft.js`를 실행하지 않는다. (`--dry-run`은 예외 — 저장 클릭만 생략)

## 3. `/write` 실행 절차

### STEP 1 — 입력 확인 (질문 먼저, 추측 금지)
- `input/photos/`, `input/videos/` 목록 확인
- 사용자 메모에서 빠진 것을 **묻는다**: 소재, 메인 키워드 후보, 협찬 여부, 확인 안 된 사실
- **사진을 전부 Read로 직접 본다.** 파일명이 아니라 실제 내용으로 판단한다

### STEP 2 — 개인정보 스캔 · 모자이크 (필수)
사진에서 식별 가능한 **타인 얼굴 · 차량 번호판 · 전화번호 · 명찰 · 주소**를 발견하면:
1. 문제 영역 좌표(0~1 상대값, **상하좌우 15% 여유**)를 담은 spec을 `drafts/`에 JSON으로 저장
2. `node scripts/mosaic.js drafts/<spec>.json` 실행 — 처리본은 `input/photos/_mosaic/`에 생성되고 **원본은 절대 덮어쓰지 않는다**
3. **처리본을 Read로 열어 실제로 가려졌는지 눈으로 확인한다.** 덜 가려졌으면 좌표를 키워 재실행
4. 초안 JSON에는 **처리본 경로**를 쓴다
- 화자 본인 얼굴도 **기본은 모자이크** (사용자가 공개를 명시한 경우만 예외)
- 검수 보고에 **처리 내역(몇 장 · 몇 영역 · 사유)** 을 포함한다

### STEP 3 — 키워드 · 페르소나 설계
- **메인 키워드 1개**: 제목 앞쪽 · 첫 문단 · 마지막 문단에 배치, 본문 5~7회, **띄어쓰기까지 검색어와 동일한 형태로 최소 1회**
- **서브 키워드 2~3개**: 소제목에 배치
- **페르소나 1명을 구체적으로 정의한다** (지역·나이·직책·상황·감정). 그 사람 한 명에게 말 걸듯 쓴다. 초안 검수 때 페르소나도 같이 보고한다

### STEP 4 — 본문 작성
「4. 글쓰기 공식」과 「5. 필수 정보 체크리스트」를 따른다.

### STEP 5 — 초안 JSON 저장 + 검수 보고
`drafts/YYYY-MM-DD-<슬러그>.json`으로 저장하고 사용자에게 보고한다. 보고에 반드시 포함:
- 제목(글자 수) / 메인·서브 키워드와 본문 등장 횟수 / 페르소나 / 예상 글자 수 / 사진 배치 순서와 이유 / 모자이크 처리 내역 / 협찬 표기 여부 / **필수 정보 체크리스트 항목별 대조 결과** / **출처 미확인이라 뺀 문장 목록**
- 자가 질문: **"모바일에서 인용구와 소제목만 훑어도 핵심이 전달되는가?"**

### STEP 6 — 승인 후 임시저장
```
node scripts/naver_draft.js drafts/<파일>.json --dry-run   :: 셀렉터 점검용 (저장 안 함)
node scripts/naver_draft.js drafts/<파일>.json             :: 진짜 임시저장
```

### STEP 7 — 이중 검증 (성공 보고 전 필수)
1. `drafts/<파일>.screenshot.png` 확인 (화면 상단만 보임 — 보조 증거)
2. **`drafts/<파일>.dump.txt` 를 Read로 열어 초안과 전문 대조** ← 이게 본검증
3. 스크립트가 출력한 **「자동 처리 결과」 블록**에서 태그/지도/동영상/소제목/사진 성공 여부 확인
4. **불일치가 하나라도 있으면 성공 보고 금지.** 원인을 찾아 고치고 다시 돌린다

## 4. 글쓰기 공식 (실전 검증됨)

### 도입
- **첫 문단 Yes-set**: 첫 2~3문장에서 페르소나의 상황·감정을 적중시켜 "맞아, 내 얘기다"를 연속으로 유도하고 **결론을 예고**한다
- **둘째 문단 권위 한 줄**: `data/authority-lines.md`에서 골라 **변형해** 툭 던지듯. 자랑·업체명·연락처 금지. 정보성 글엔 **솔직함형**이 가장 강력
- **후킹 패턴은 매번 다르게**: 손실 회피형 / 현장 몰입형 / 반전형 / 공감형 (직전 글과 같은 패턴 금지 — `data/trends.md`에 사용 이력을 남긴다)

### 홍보 냄새 제거
- 정보성 글 본문에 **업체명 금지** (CTA에서만 1회)
- 연락처는 글 전체 **1회**
- 업체명은 본문 **3회 이내**

### 가독성 (모바일 기준)
- 한 문장 = 한 줄
- 한 블록 3~5줄
- **리듬 파괴 장치(인용구/구분선/사진/소제목)를 300~400자마다**
- 핵심 문장은 **인용구로 글당 2~4개**
- **텍스트만 500자 연속이면 실패작**
- 표는 `✔ 항목 — 내용` 체크리스트로 대체

### 기본 세팅
- 1,800~2,500자 (정보성은 3,000자까지)
- 사진 10~15장 (장당 텍스트 2~4문단)
- 제목 25~32자
- 유사문서·저품질 회피: 도입 패턴 매번 변경 / 사진 재사용 금지 / 외부링크 1개 / 광고 어휘·제목 특수문자 금지

### 캡션
- 사진은 **분석한 스토리 순서**로 배치한다 (파일 순서 아님)
- 캡션에도 키워드를 1~2회 자연스럽게 — **전체 사진의 절반 정도만**

## 5. 업종별 필수 정보 체크리스트 — 스포츠 이슈

초안 검수 때 **항목별로 대조한다.** 확인 안 된 항목은 **지어내지 말고 묻거나 뺀다.**

### 5-A. 사실 6종 세트 (이슈 1건마다)
```
✔ 누가 — 인물/팀명 정확한 표기 (예명·등번호·소속 포함)
✔ 언제 — 날짜와 (가능하면) 한국시간 기준 시각
✔ 어디서 — 경기장·행사장·매체명
✔ 무엇을 — 사건의 핵심 한 문장
✔ 수치 — 기록·스코어·순위·금액 등 검증 가능한 숫자
✔ 출처 — 사용자가 제공한 원문 (매체명 + 날짜). 없으면 그 문장은 쓰지 않는다
```

### 5-B. 출처 규칙 (이 주제의 절대선)
- **사용자가 준 자료에 없는 사실은 한 문장도 쓰지 않는다.** 기억에 의존한 경기 결과·이적설·열애설은 전부 금지
- "~로 알려졌다", "~라는 말이 나온다" 같은 **출처 없는 전언체로 우회하지 않는다.** 출처가 없으면 삭제한다
- **추측과 사실을 문장 단위로 분리한다.** 개인 의견은 "제 판단으로는"처럼 주체를 명시한다
- 미확정 사안(이적·계약·열애 등)은 **"공식 발표 없음"을 명시**한다
- 범죄·의혹 보도는 **"혐의"·"조사 중" 표현을 유지**하고 단정하지 않는다. 확정 판결 전 단정은 명예훼손이 된다
- 외부링크는 **1개** — 있다면 1차 출처(공식 발표·구단 공지)를 쓴다

### 5-C. 사진 규칙 (이 주제의 최대 함정)
- **사용자가 직접 촬영했거나 사용 권리를 가진 사진만 쓴다.** 포털·SNS·기사에서 가져온 사진은 쓰지 않는다
- 사진마다 출처를 사용자에게 확인하고, 불명확하면 **그 사진을 빼고 진행한다**
- 관중석·일반인이 찍힌 사진은 **전원 모자이크** (STEP 2)

### 5-D. 글 구성 체크
```
✔ 핵심 결론을 첫 문단에 예고했는가
✔ 시간순 정리(타임라인)가 들어갔는가
✔ 왜 이게 중요한지(맥락·배경)를 한 단락 이상 설명했는가
✔ 반대 시각 또는 남은 변수 1개를 넣었는가  ← 단정 회피 + 체류시간
✔ 향후 일정(다음 경기·발표 예정일)을 마지막에 넣었는가
```

### 5-E. "아카이브" 필명이 요구하는 것 (이 블로그의 차별점)
필명이 **스포츠 이슈 아카이브**다. 속보로는 언론사를 못 이긴다. 대신 **정리본으로 이긴다.**
```
✔ 타임라인 — 날짜별로 무슨 일이 있었는지 순서대로 (검색자가 제일 찾는 형태)
✔ 과거 같은 사례 1건 — 사용자가 자료를 준 경우만. 없으면 넣지 않는다
✔ 앞으로 확인할 날짜 — 다음 경기일, 발표 예정일, 마감 기한
✔ "이 글은 추가 발표가 나오면 이어서 정리한다"는 예고 → 재방문 유도
```
- 속보성 어휘("속보", "단독")는 쓰지 않는다. 우리는 1차 취재원이 아니다
- 같은 사안을 여러 번 쓸 때는 **새 글을 양산하지 말고 기존 글에 이어 쓰는 것**을 우선 검토한다 (유사문서 회피)

## 6. 사진 · 영상 처리

### 모자이크 (`scripts/mosaic.js`) — 구현 함정 둘
- 좌표 기준은 반드시 **EXIF 회전 보정 후(보이는 화면 기준)** 로 잡는다
- sharp는 **한 파이프라인에 resize를 1회만** 적용하므로, **축소 → 버퍼 → 확대(nearest)** 로 2단계 분리한다

spec JSON 포맷:
```json
{
  "regions": [
    { "image": "input/photos/IMG_1.jpg",
      "boxes": [ { "x": 0.31, "y": 0.12, "w": 0.18, "h": 0.22, "why": "관중 얼굴" } ] }
  ]
}
```

### 동영상 자동 첨부
- `input/videos/`에 영상이 있으면 초안의 `video` 필드에 넣는다
- **항상 첫 `text` 블록 직후에 삽입된다** (D.I.A.+ 가산 요소)
- 영상 제목 필수 · **40자 제한** (`video.title` > 글 제목 > 기본값 순)
- 업로드에 **수 분** 걸릴 수 있다 — 타임아웃 났다고 바로 재실행하지 않는다

## 7. 초안 JSON 포맷

```json
{
  "title": "제목 25~32자",
  "persona": "누구에게 말하는 글인지 한 문장",
  "mainKeyword": "메인 키워드",
  "subKeywords": ["서브1", "서브2"],
  "sponsored": false,
  "sources": ["OO일보 2026-09-14 <기사 제목>"],
  "tags": ["태그1", "태그2"],
  "place": { "query": "검색어", "name": "정확한 상호명" },
```

## 9. 실측 지식 (수십 시간 디버깅으로 확인 — 추측으로 대체 금지)

### 구조
- 에디터는 **`iframe#mainFrame` 안**에 있다 (프레임이 없으면 페이지 자체가 에디터)
- 글쓰기 진입 URL: `https://blog.naver.com/GoBlogWrite.naver`
- 브라우저 뷰포트는 **1600×1000 이상** — 1400 이하에서는 패널이 열릴 때 속성 툴바가 잘려 서식 버튼 클릭이 불안정해진다

### 본문/제목 (가장 많이 깨지는 부분)
- 본문 셀렉터는 **`.se-section-text p.se-text-paragraph`로 한정**한다. 제목도 내부적으로 같은 문단 구조(`p.se-text-paragraph`)를 쓰기 때문에, 범위를 넓게 잡으면 **본문 클릭이 제목을 오염시켜 제목이 깨지고 본문 첫 줄이 사라진다**
- 제목은 **`.se-title-text`**
- **입력 순서: 본문 전체 먼저 → 제목은 맨 마지막.** 제목 직후 본문을 치면 레이스 컨디션으로 섞임이 재현된다
- 제목 입력 후 **실제 값을 읽어 초안과 비교**하고, 불일치면 전체 선택·삭제 후 재입력
- 본문 첫 줄도 저장 전에 **앞 10여 자 포함 여부**를 검사해 누락이면 맨 앞에 보정 삽입

### 입력
- 한글은 반드시 **`keyboard.insertText()`** — `keyboard.type()`은 IME 조합이 꼬여 오탈자 발생
- **이모지는 별도 호출로 분리 삽입** (함께 넣으면 이모지 뒤 텍스트가 유실된다)
- `text` 블록이 연달아 오면 문단이 빈 줄 없이 붙어 렌더링된다 → **다음 블록도 `text`일 때만** 끝에서 Enter를 한 번 더 누른다. 사진·소제목·인용구 앞은 에디터가 자체 여백을 준다

### 버튼 (추측 클래스명 금지)
- 인용구: `se-insert-quotation-default-toolbar-button`
- 구분선: `se-insert-horizontal-line-default-toolbar-button`
- 사진: `button.se-image-toolbar-button` (클릭하면 파일선택창이 뜬다)
- 글자 크기 드롭다운 열기: `se-font-size-code-toolbar-button`
- 문단 서식 드롭다운 열기: `se-text-format-toolbar-button`
- 도움말 패널 닫기: `.se-help-panel-close-button`
- 동영상 팝업: `.se-popup-video-upload` / "동영상 추가" `button.nvu_btn_append.nvu_local` / 제목 `.se-popup-video-upload input[placeholder*="제목"]` / 닫기 `button.nvu_btn_close`
- 임시저장: 클래스가 `save_btn__` + 해시라 **`button[class*="save_btn"]`** 로 잡고 "저장" 텍스트 버튼을 폴백으로 둔다

### 소제목 서식
- **볼드 토글로 하지 말 것** — 스마트에디터에선 선택 영역이 안 잡혀 실패한다
- **문단 서식 드롭다운(`se-text-format-toolbar-button` → "소제목")** 을 쓰면 캐럿만 놓여도 문단 전체에 적용된다
- 기본 크기 30은 너무 커서 **19(`fs19`)** 로 낮춘다
- **순서가 핵심: 서식 → 크기 → 텍스트 입력.** 입력 후에 바꾸면 이미 쓴 글자에 적용되지 않는다
- 입력 후 다음 문단은 **"본문"으로 명시 복귀**시키고, 드롭다운 라벨을 다시 읽어 적용 여부를 검증한다

### 태그
- 우상단 발행 버튼으로 **패널을 열고** `input#tag-input`에 태그마다 **입력 + Enter로 칩 확정** (입력 전 앞의 `#` 제거, 최대 30개)
- **Escape로 패널만 닫고** 그 다음 임시저장
- 패널 안에 진짜 발행 버튼이 있으므로 **발행 차단 가드(절대 규칙 2)가 전제**다
- 태그 검증은 태그 영역 텍스트를 `#`로 쪼개 센다 (**칩 클래스는 해시가 바뀌므로 의존 금지**)

### 지도(플레이스)
- 지도 툴바 버튼 → 장소명 검색 → 결과가 여러 개면 `place.name`과 **공백 제거 정확 일치 → 부분 포함 → 첫 결과** 순으로 선택
- 결과 항목의 "추가" 버튼은 **hover 전에는 not visible** — 그냥 클릭하면 타임아웃. **항목 hover 후 클릭**(폴백은 DOM 직접 click)
- "추가" 전까지 **확인 버튼은 disabled**
- **장소 팝업은 Escape로 안 닫힌다 → 반드시 팝업 닫기 버튼 사용.** 안 닫으면 dim 레이어가 남아 이후 모든 클릭이 `intercepts pointer events`로 실패한다

### 동영상
- 동영상 툴바 버튼 → 업로드 팝업의 **"동영상 추가" 버튼이 파일 선택창을 띄운다**
- 제목 입력 필수 (40자 제한)
- 팝업을 확실히 닫지 않으면 dim 잔류로 이후 클릭 전부 실패 — **닫기 실패 시 DOM에서 강제 제거 폴백**까지 넣는다

### 기타
- 진입 시 **"작성 중인 글" 팝업은 새로 쓰기(`.se-popup-button-cancel`)** 로 닫는다
- 디버깅 재실행이 반복되면 네이버 "저장 글"에 실패본이 쌓인다 → 완료 보고 때 **사용자에게 직접 정리하라고 안내** (자동 삭제 금지 — 파괴적 작업)
- **네이버 블로그 본문은 WebFetch 불가(도메인 차단)일 수 있다** — 재시도하지 말고 바로 사용자에게 본문 붙여넣기를 요청한다
- **`--dry-run`을 항상 먼저** — 셀렉터 수정 중에 "저장 글" 목록에 실패본이 쌓이지 않게
- 셀렉터는 네이버가 수시로 바꾼다. 실패 시 `probe_selectors.js`로 실제 DOM을 떠서 **실측 후 수정**하고, **3회 실패하면 수동 붙여넣기용 원고를 출력**한다

## 10. 자가 검증 원칙 (이 툴의 품질 엔진 — 가장 중요)

모든 단계에서 **"했다"가 아니라 "됐는지 확인했다"** 로 끝낸다.

1. **이중 검증**: 임시저장 후 (a) 스크린샷 + (b) 에디터 문서의 제목·본문 **전체 텍스트 덤프**를 파일로 추출해 초안과 전문 대조한다. 스크린샷은 화면 상단만 보이므로 **텍스트 덤프가 본검증**이다. 불일치하면 **성공 보고 금지**
2. **셀렉터가 실패하면 추측으로 고치지 말고**, 실제 DOM을 검사하는 일회용 스크립트(`probe_selectors.js`)로 실측한 뒤 고친다
3. 문제를 해결하면 **원인과 해결책을 아래 「11. 문제 해결 기록」에 적고**, 안정 버전 스크립트를 `.working.js`로 백업한다
   - `.working.js` 는 **실제 네이버에서 임시저장까지 성공하고 전문 대조가 일치한 버전**에만 붙인다. 아직 검증 안 된 코드에 붙이지 않는다
   - 예: `copy scripts\naver_draft.js scripts\naver_draft.working.js`
4. 초안 검수 자가 질문: **"모바일에서 인용구와 소제목만 훑어도 핵심이 전달되는가?"**

## 12. 발행 체크리스트 (임시저장 후 사용자 안내)

태그 5~10개 · 지도 · 동영상 · 소제목 서식은 **스크립트가 자동 처리**하므로,
실행 로그의 **「자동 처리 결과」** 블록을 확인해 **❗수동 필요로 찍힌 항목만** 안내한다.

그 외에 항상 안내할 수동 항목:
```
✔ 타겟 활동 시간대에 발행 (스포츠/연예는 이슈 직후 + 출퇴근·심야 시간대)
✔ 발행 후 24시간 수정 금지
✔ 발행 주기는 일 2~3회
✔ 네이버 "저장 글" 목록에 쌓인 실패본은 직접 정리 (자동 삭제 안 함)
```
