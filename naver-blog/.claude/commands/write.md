# /write — 초안 작성

사용자 메모: $ARGUMENTS

## 반드시 먼저 읽을 것
`CLAUDE.md` 전체, 그리고 `data/blogger-profile.md`, `data/profile.md`, `data/authority-lines.md`,
`data/photo-guide.md`, `data/trends.md`, `data/style-profile.md`.
협찬 가능성이 있으면 `data/sponsored-disclosure.md`도.

## 절차 (CLAUDE.md 「3. /write 실행 절차」를 따른다)

### 1) 입력 확인 — 추측 금지, 부족하면 묻는다
- `input/photos/`, `input/videos/` 목록 확인
- **사진을 전부 Read로 직접 본다.** 파일명이 아니라 실제 내용으로 판단한다
- 메모에서 빠진 걸 **질문한다**:
  - 소재의 사실 6종 세트(누가/언제/어디서/무엇을/수치/**출처**)
  - **출처 원문** — 없는 사실은 한 문장도 쓰지 않는다
  - 사진 출처·촬영 권리 (직접 촬영본인가)
  - 메인 키워드 후보
  - **협찬·체험단 여부** (기본값은 비협찬이지만 매번 1회 확인)

### 2) 개인정보 스캔 → 모자이크
타인 얼굴·번호판·전화번호·티켓 정보가 보이면 spec JSON을 `drafts/`에 쓰고
`node scripts/mosaic.js drafts/<spec>.json` 실행 → **처리본을 Read로 열어 눈으로 확인** → 초안엔 처리본 경로.

### 3) 키워드 · 페르소나 설계
메인 1개(제목 앞쪽·첫 문단·마지막 문단, 본문 5~7회, 띄어쓰기까지 검색어와 동일한 형태 1회 이상)
서브 2~3개(소제목 배치). 페르소나 1명을 구체적으로 정의(지역·나이·직책·상황·감정).

### 4) 본문 작성
- 첫 문단 Yes-set(상황·감정 적중 + 결론 예고)
- 둘째 문단 권위 한 줄(`authority-lines.md`에서 골라 **변형**, 정보성 글엔 솔직함형)
- 후킹 패턴은 `data/trends.md` 이력을 보고 **직전 글과 다르게**
- 리듬 파괴 장치 300~400자마다, 인용구 2~4개, 텍스트만 500자 연속 금지
- 1,800~2,500자 / 제목 25~32자
- **스포츠·연예 체크리스트**(CLAUDE.md 5번) 항목별 대조

### 5) 초안 저장 + 검수 보고
`drafts/YYYY-MM-DD-<슬러그>.json` 으로 저장하고 보고한다:
```
제목(글자 수) / 메인·서브 키워드 본문 등장 횟수 / 페르소나 / 예상 글자 수
사진 배치 순서와 이유 / 모자이크 처리 내역(몇 장·몇 영역·사유)
협찬 표기 여부 / 필수 정보 체크리스트 항목별 대조 / 출처 미확인이라 뺀 문장 목록
자가 질문: "모바일에서 인용구와 소제목만 훑어도 핵심이 전달되는가?"
```
**여기서 멈추고 사용자 승인을 받는다.** (절대 규칙 6)

### 6) 승인 후
```
node scripts/naver_draft.js drafts/<파일>.json --dry-run
node scripts/naver_draft.js drafts/<파일>.json
```

### 7) 이중 검증 — 이걸 해야 끝이다
1. `drafts/<파일>.dump.txt` 를 **Read로 열어 초안과 전문 대조** (본검증)
2. `drafts/<파일>.screenshot.png` 확인 (보조)
3. 로그의 **「자동 처리 결과」** 에서 ❗수동 필요 항목만 사용자에게 안내
4. 불일치가 하나라도 있으면 **성공 보고 금지** — 원인 찾아 수정 후 재실행
5. 「12. 발행 체크리스트」의 수동 항목 안내
